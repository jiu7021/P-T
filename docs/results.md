## Module A-2. 공간 특징 추출 — **WM-811K 실데이터**

실행: `.venv/bin/python src/features/spatial.py` (2,128,718행, 약 25초)

### 스캔 순서 정의 (미래 정보 누수 방지의 기준점)

**serpentine(뱀 모양)**: 행 0은 왼→오른쪽, 행 1은 오른→왼쪽, 이하 반복.

- 근거 **(통상범위)**: 프로버는 행 끝에서 시작점으로 되돌아가지 않고 방향을 바꿔
  진행하는 편이 스텝 이동 거리가 짧다.
- 단방향 래스터로 정의하면 모든 행에서 "이미 테스트된 이웃"이 항상 왼쪽에만
  생겨 좌우 비대칭 편향이 특징에 들어간다. serpentine은 행마다 방향이 바뀌어
  이 편향이 상쇄된다.

### 추출한 특징 (다이당 12개)

| 특징 | 정의 | 미래 정보 여부 |
|---|---|---|
| `r_norm` | 유효 다이 무게중심 기준 거리 / 최대 거리 | 기하학적, 무관 |
| `edge_dist`, `edge_dist_norm` | 유효 영역 거리 변환(EDT) 값 | 기하학적, 무관 |
| `nb8_tested_cnt` | 8-이웃 중 **이미 테스트된** 다이 수 | 과거만 |
| `nb8_tested_fail_rate` | 위 이웃들의 불량 비율 | 과거만 |
| `nb_r2_tested_cnt` | 유클리드 반경 2 이내 이웃 중 이미 테스트된 수 | 과거만 |
| `nb_r2_tested_fail_rate` | 위 이웃들의 불량 비율 | 과거만 |
| `prev_wafer_fail` | 같은 로트 직전 웨이퍼 동일 좌표 불량 여부 | 이전 웨이퍼, 무관 |
| `scan_rank`, `scan_progress` | 웨이퍼 내 테스트 순번 / 진행률 | 자기 순번, 무관 |

명세의 "반경 2 이내 이웃 불량 비율"에는 원래 '이미 테스트된' 조건이 붙어 있지
않았으나, **8-이웃과 동일하게 과거 다이만 쓰도록 제한했다.** 반경 2에만 미래
정보를 허용하면 그 경로로 누수가 들어온다.

### 잘 안 되는 부분 — 숨기지 않고 기록한다

1. **Loc의 F1이 0.451로 가장 낮다.** 실제 Loc 40장 중 Edge-Loc으로 10장,
   Center로 7장이 갔다. Loc / Edge-Loc / Center는 "국소 밀집 불량이 어디에
   있는가"만 다른 라벨이라 경계가 연속적이다. WM-811K는 라벨 판정 기준을
   공개하지 않으므로(`data_limits.md` L4) 라벨 자체의 모호성과 모델의 한계를
   이 결과만으로 분리할 수 없다.
2. **Scratch의 recall이 0.564로 낮다.** Edge-Loc 8장, none 6장으로 샜다.
   Scratch는 불량률이 10.89%로 낮아(표 A-1) 선형 구조가 64×64 리샘플링에서
   흐려지는 것이 원인으로 보인다. 확인하지 않은 추정이다.
3. **과적합.** train loss는 0.016까지 떨어졌으나 val macro-F1은 30에폭 부근
   0.82에서 포화했다(60에폭 기준 val 0.811, best 0.823). 데이터 증강이나
   정규화를 더 넣으면 개선 여지가 있으나, 성능이 이 프로젝트의 주장 대상이
   아니므로 추가 튜닝하지 않고 한계로 남긴다.
4. **val 0.823 → test 0.763.** val로 가중치를 고른 만큼 val이 낙관적이다.
   보고 기준은 test다.

### Grad-CAM — 라벨만 내놓지 않는다

마지막 conv 특징맵(64ch, 8×8)에 대한 클래스 점수의 기울기를 채널 중요도로 삼아
가중합하고 64×64로 되돌린다. 훅 대신 `torch.autograd.grad`로 직접 받는다.

### 이 표의 적용 한계 — 화면에 상시 노출한다

1. **Carinthia-S가 어느 공정 단계의 층인지 공개되지 않았다.** 따라서 후보 목록은
   "이 형태의 결함이 일반적으로 어느 공정에서 비롯되는가"이지 "이 이미지의 원인이
   무엇인가"가 아니다.
2. 결함 형태 하나로 원인 공정이 확정되는 경우는 없다. 공정 이력, 발생 시점,
   웨이퍼 내 분포, 재료 분석(EDX 등)이 함께 있어야 한다.
3. 후보는 배타적이지 않다. 여러 후보가 동시에 성립할 수 있다.
4. **이 매핑은 학습 대상이 아니다.** `src/model/cause_lookup.py`는 파라미터가 없고
   YAML을 조회할 뿐이다. AI가 원인 공정을 예측하지 않는다는 원칙을 코드 구조로 지킨다.

실행: `.venv/bin/python src/sim/fail_address.py`

> 셀 단위 Fail Address 비트맵은 **공개 데이터가 존재하지 않는다**(`data_limits.md` L3).
> WM-811K는 다이 단위 합불만 제공하며 칩 내부 셀 주소는 없다.
> 여기의 주소는 전부 합성이며, **규칙 기반 판별기**로 처리한다. 모델이 아니다.

### 데이터 계층 — 혼동하지 말 것

| 계층 | 단위 | 본 프로젝트의 데이터 |
|---|---|---|
| 웨이퍼 맵 | 다이 1개 = 점 1개 (pass/fail) | WM-811K **실데이터** |
| Fail Address | 다이 **내부** 셀 주소 (X, Y) | **합성** (공개 데이터 없음) |
| SEM 이미지 | 결함 1개의 확대 이미지 | Carinthia-S **실데이터** |

### 주소 표기

**16진수다. 12진수가 아니다**(a~f가 나타난다). 주소 공간은 X 16bit / Y 12bit로
잡았다 — **(가정치)**. SK하이닉스 공개 영상의 Fail Address 화면에서 X가 4자리
16진수(`1a3d`), Y가 1~3자리(`0` ~ `2e1`)로 표기된 것을 근거로 자리수만 맞췄다.
비트 폭의 절대값은 결론에 영향을 주지 않는다. 판별이 주소의 절대값이 아니라
**같은 주소를 공유하는 fail의 개수와 분포**로 이루어지기 때문이다.

영상 화면의 Y 값(`0,1,10,11,20,21,…` / `2a0,2a1,2b0,2b1,…`)을 16진수로 풀면
**16 간격으로 2개씩 묶인 구조**다. 합성기의 `stride=16, pair=2`가 이 형태를 재현한다.
실제 주소 매핑 구조는 공개되어 있지 않다 — **(가정치)**.

### 불량 모드 5종

| 모드 | 형태 | 물리적 해석 |
|---|---|---|
| `single_bit` 싱글비트 | 고립된 단일 셀 | 셀 개별 결함, 랜덤 파티클 |
| `row_fail` 로우성 | 같은 X 다수 | 워드라인 단선/단락, 로우 디코더 이상 |
| `column_fail` 칼럼성 | 같은 Y 다수 | 비트라인 단선/단락, 센스앰프 이상 |
| `block_fail` 블락성 | 좁은 X·Y 구간에 밀집 | 매트 단위 전원/기준전압 이상, 국소 공정 결함 |
| `cross_fail` 크로스 | 로우 + 칼럼 동시 | 교차점 회로/상위 제어 이상. 리페어 자원 소모 최대 |

### 판별 규칙 — 점수는 '설명 비율'이지 확률이 아니다

각 구조가 설명하는 fail 집합의 크기 비율을 점수로 쓴다. `single_bit` 점수는
**어느 구조로도 설명되지 않은 fail의 비율**이며, 합집합으로 계산한다.

> 초기 구현에서 `single_bit`를 "최대 구조 하나가 설명하지 못한 비율"로 계산해
> row 50% + column 50%인 크로스가 싱글비트와 동점이 되었다. 이때 크로스 판별
> 정확도가 200회 중 27회(13.5%)였다. 합집합 기준으로 고쳐 200/200이 되었다.

상위 두 후보의 점수 차가 `ambiguous_margin`(0.20) 미만이면 **경계 사례로 표시하고
단정하지 않는다.**

### 판별 결과 예시 (합성 row_fail, fail 22건)

```
     X | Y             판별: 로우성 (row_fail)  점수 0.909
  -----+-----          근거
  4aa8 | c8c             최다 X = 0x6323 : 20건 (90.9%)
  6323 | 1b8             최다 Y = 0xc8c  : 1건  (4.5%)
  6323 | 1b9             최밀 블록 0x6323~0x6332 / 0x1b8~0x1c7 : 2건 (9.1%)
  6323 | 1c8
  6323 | 1c9           ← X가 고정된 채 Y만 16 간격 쌍으로 늘어선다
  6323 | 1d8
   …
```

### 자기검증 — 합성한 모드를 판별기가 되찾는가

각 모드 200회, 산발 잡음 0~3건 포함:

| 합성＼판별 | single_bit | row_fail | column_fail | block_fail | cross_fail |
|---|---:|---:|---:|---:|---:|
| single_bit | **200** | 0 | 0 | 0 | 0 |
| row_fail | 0 | **200** | 0 | 0 | 0 |
| column_fail | 0 | 0 | **200** | 0 | 0 |
| block_fail | 7 | 0 | 0 | **193** | 0 |
| cross_fail | 0 | 0 | 0 | 0 | **200** |

**일치 993/1000 (99.3%)**

block_fail 오판 11/400건의 원인을 확인했다: fail 총수가 적을 때(중앙값 10건)
블록 창 안의 fail이 5건에 그쳐 `block_min_count=6` 임계를 넘지 못한다
(count 미달 7건, ratio 미달 1건). **임계값의 한계이지 판별 논리의 오류가 아니다.**

> 이 수치는 '판별기가 의도한 형태를 구분한다'는 최소 확인일 뿐이다.
> 합성과 판별이 같은 가정 위에 서 있으므로 실제 라인 데이터에 대한 성능이 아니다.

### 임계값 민감도 — 전부 가정치이므로 반드시 본다

자기검증 일치율(각 모드 120회):

| 임계값 | 변화에 따른 일치율 |
|---|---|
| `line_min_count` | 2: 99.3% / 3: 99.3% / **4: 99.3%** / 6: 96.2% / 8: 93.7% |
| `line_min_ratio` | 0.15: 99.3% / 0.2: 99.3% / **0.3: 99.3%** / 0.4: 97.5% / **0.5: 82.7%** |
| `block_min_count` | 3: 99.7% / 4: 99.7% / **6: 99.3%** / 8: 98.8% / 10: 96.2% |
| `block_min_ratio` | 0.2: 99.3% / 0.3: 99.3% / **0.4: 99.3%** / 0.5: 99.3% / 0.6: 98.2% |

(굵은 값이 채택한 기준값)

- **`line_min_ratio`가 가장 민감하다.** 0.5로 올리면 82.7%까지 떨어진다.
  라인성 fail에 산발 잡음이 섞이면 비율이 희석되기 때문이다.
- `block_min_count`를 3~4로 낮추면 99.7%로 오르지만, 합성 데이터에서만 확인된
  값이다. 실제 산발 불량을 블록으로 오인할 여지를 남기지 않기 위해 6을 유지한다.
  **유리한 쪽 수치를 택하지 않았다.**

4. 데모용 가짜 판정은 `source="demo"`로 표시하고 학습 대상에서 제외한다.

검증 예: 로우성 표본(최다 X가 전체의 90.9%)에서 `line_min_ratio`를 올리면

|---:|---|
| 0.30 | 로우성 (설명 비율 0.909) |
| 0.80 | 로우성 (설명 비율 0.909) |
| **0.92** | **싱글비트 (설명 비율 1.000)** |
| 0.99 | 싱글비트 |

0.909를 넘는 순간 임계 미달이 되어 판별이 뒤집힌다.

### 구현 중 잡은 문제 2건

1. **`none` 그룹의 Dice를 0.000으로 표시했다.** 정답 마스크가 비어 있으면 Dice는
   0이 아니라 **정의되지 않는다.** 0으로 두면 성능이 나쁜 것처럼 읽힌다.
   `null`로 바꾸고 화면에 "정의 불가 — 정답 마스크가 비어 있음"으로 표기했다.
   대신 오검출 픽셀 수를 보여준다.
2. **SEM 원본이 화면에서 균일한 회색으로 보였다.** 렌더 오류가 아니라 원본이
   저대비인 것이었다 — 밝기 표준편차 중앙값 **10.8**(0~255), 결함은 배경보다
   평균 **29 어둡다**. 2~98 백분위 선형 스트레칭을 **표시용 토글**로 넣었다
   (표준편차 10.4 → 48.5). 모델 입력과 측정값은 원본 그대로를 쓴다는 문구를
   화면에 명시했다.

## EDS 웨이퍼 테스트 — **불량 위치는 실데이터, 측정값과 fail address는 합성**

실행: `.venv/bin/python src/sim/eds.py` (약 2.5분)

> **단계 정정.** 초기 설계는 웨이퍼 테스트 흐름 안에 SEM 이미지 분석을 넣었다. 잘못이다.
> 웨이퍼 테스트(EDS)는 프로브로 전압을 인가해 출력이 규격에 맞는지 보는 **전기 시험**이고,
> 결함 이미지 분석은 걸러진 다이를 뜯어보는 **FA 단계**다(`data_limits.md` L0).

### 시험 항목

| 순서 | 항목 | 온도 | 무엇을 재나 | 규격 | 리페어 대상 |
|---:|---|---|---|---|---|
| 1 | 오픈/쇼트 | 25 °C | 핀 전압 | -1.20 ~ -0.40 V | 아니오 (칩 전체) |
| 2 | 대기 전류 | 25 °C | 무동작 시 전류 | ≤ 3.0 mA | 아니오 |
| 3 | 동작 전류 | 25 °C | 읽기·쓰기 중 전류 | ≤ 120 mA | 아니오 |
| 4 | 기능 시험 | 25 °C | 쓴 값과 읽은 값 일치 | fail bit 0 | 예 (셀 어레이) |
| 5 | 기능 시험 | 85 °C | 위와 같음 | fail bit 0 | 예 |
| 6 | 리텐션 | 85 °C | 리프레시 중단 후 보유 시간 | ≥ 64 ms | 예 |

규격 절대값은 **(가정치)**다. 항목 간 상대 관계만 물리적으로 타당하게 잡았다.

### Good / Repairable / Fail을 가르는 논리

메모리 칩에는 **여분 행·열**이 미리 들어 있다. 불량 셀이 나오면 그 행(또는 열)을
통째로 여분으로 갈아끼운다(퓨즈를 끊어 주소 재배정).

| 등급 | 조건 |
|---|---|
| **Good** | 모든 시험을 규격 안에서 통과 |
| **Repairable** | 셀 어레이 불량이 있으나 여분 행·열 안에서 전부 덮임 |
| **Fail** | 여분이 모자라거나, 리페어로 대체 불가한 칩 전체 특성 불량 |

**칩 전체 특성 불량은 리페어가 성립하지 않는다.** 여분 행·열은 셀 어레이를 대체하는
자원이다. 전류가 규격을 넘거나 배선이 끊긴 것은 갈아끼울 대상 자체가 없다.

리페어 분석은 **must-repair 우선 탐색**이다:

1. 어떤 행의 fail 수가 남은 여분 **열**보다 많으면 → 열로 못 덮음 → 반드시 행 배정
2. 어떤 열의 fail 수가 남은 여분 **행**보다 많으면 → 반드시 열 배정
3. 강제 배정 후 남은 fail을 남은 여분으로 덮을 수 있는지 탐색
4. 전부 덮이면 Repairable, 남으면 Fail

출처: H. Kwon, J. Moon, J. Byun et al., "Linear search algorithm for repair analysis with
4 spare row/4 spare column," *IEEE APASIC*, pp. 269-272, 2000. doi:10.1109/apasic.2000.896960 /
D. Bhavsar, "An algorithm for row-column self-repair of RAMs," *ITC*, pp. 311-318, 1999.
doi:10.1109/test.1999.805645

### 자체 검증 — 합성이 실데이터 판정을 뒤집지 않았는가

어느 다이가 불량인지는 실데이터가 정한다. 합성은 **왜** 불량인지만 만든다.
정상 다이가 Good이 아니면 합성이 판정을 뒤집은 것이다.

| 검증 | 결과 |
|---|---|
| 실데이터 정상 → Good | 1,638,172개, 불일치 **0** |
| 실데이터 불량 → Repairable/Fail | 490,546개, 불일치 **0** |

검증에 실패하면 결과를 저장하지 않고 종료한다(종료코드 1).

> **초기 구현은 이 검증에서 실패했다.** 정상 다이 **275,159개**가 Fail/Repairable로
> 갔다. 원인은 리텐션을 `105 + 22·f − 25·r + 잡음`처럼 선형식과 정규잡음으로 만든
> 것이었다. `f`가 음수로 크면 값이 규격(64 ms) 아래로 내려간다.
> 로지스틱으로 유계화해 규격 안에 가두되 공간 상관 구조는 유지하도록 고쳤다.
> 수정 후 정상 다이 65,223개 표본에서 규격 위반 0을 확인했다.

### 민감도 결론 — 숨기지 않는다

| 가정 | 결과가 움직인 폭 |
|---|---:|
| 여분 2~8행/열 | Repairable 11.12% ~ 16.00% (**4.88%p**) |
| 리페어 불가 0.10~0.60 | Fail 10.48% ~ 19.68% (**9.20%p**) |
| 불량 모드 배분 | Repairable 8.57% ~ 19.63% (**11.06%p**) |

1. **가장 민감한 것은 불량 모드 배분(11.06%p)이다.** 이 표(`MODE_MIX`)는 근거가 되는
   공개 통계가 없는 순수 가정이다. Repairable 비율의 **절대값을 인용해서는 안 된다.**
2. **여분 개수를 2배로 늘려도 Repairable은 4.88%p밖에 늘지 않는다.** 블락성이
   여분을 8개로 늘려도 안 덮이기 때문이다. 리페어 자원을 늘리는 것보다
   **블락성 불량 자체를 줄이는 편이 효과가 크다**는 것을 시사한다.
   이것은 가정 변화에 견디는 결론이다.
3. 결론 중 **모드별 성공률의 순서**(라인성 ≫ 블락성)는 모든 조건에서 유지된다.
   흔들리는 것은 절대 비율이다.

## SECOM 공정 센서 수율 분석 — **실데이터만. 합성 없음.**

실행: `.venv/bin/python src/data/load_secom.py` → `src/model/secom_yield.py`

이 모듈만은 가정이 하나도 들어가지 않는다. 실제 fab 라인에서 89일간 기록된
공정 센서 590개(전처리 후 442개)와 웨이퍼 1,567장의 합불 결과를 그대로 쓴다.

### [표 S-1] 월별 fail률 — 드리프트가 실재한다

| 월 | 웨이퍼 | fail | fail률 |
|---|---:|---:|---:|
| 2008-07 | 63 | 14 | **22.22%** |
| 2008-08 | 555 | 51 | 9.19% |
| 2008-09 | 590 | 17 | **2.88%** |
| 2008-10 | 359 | 22 | 6.13% |

fail률이 22.2%에서 2.9%로 8배 가까이 흔들린다. **이 사실이 분할 방식을 결정한다.**

### 분할 원칙 — 시간 순

무작위로 섞어 나누면 **미래 웨이퍼로 학습해 과거를 맞히는** 셈이 된다. 실제
라인에서는 과거로 학습해 다음 로트를 판단한다. 앞 70%를 학습, 뒤 30%를 검증으로 썼다.

| 구간 | 기간 | 웨이퍼 | fail | fail률 |
|---|---|---:|---:|---:|
| 학습 | 07-19 ~ 09-26 | 1,096 | 78 | 7.12% |
| 검증 | 09-26 ~ 10-17 | 471 | 26 | 5.52% |

결측 대치값(중앙값)과 표준화 통계도 **학습 구간에서만** 계산한다. 검증 구간 값을
쓰면 미래 정보가 샌다. Module A-2에서 이웃 다이 특징에 적용한 원칙과 같다.

### [표 S-2] 분할 방식이 결론을 바꾼다 — 이 절이 핵심이다

주 지표는 PR-AUC다. fail이 6.64%뿐이라 accuracy는 의미가 없다(전부 pass로 찍어도 93.4%).

| 분할 | 모델 | PR-AUC | 기저율 | 기저 대비 | ROC-AUC |
|---|---|---:|---:|---:|---:|
| **시간 순** | 로지스틱 | 0.0697 | 0.0552 | 1.26배 | 0.593 |
| **시간 순** | LightGBM | 0.0636 | 0.0552 | 1.15배 | **0.551** |
| 무작위 | 로지스틱 | 0.1070 | 0.0573 | 1.87배 | 0.639 |
| 무작위 | LightGBM | **0.1619** | 0.0573 | 2.82배 | **0.733** |

**무작위 분할이 PR-AUC를 2.5배 부풀린다**(LightGBM 0.0636 → 0.1619).
ROC-AUC도 0.551 → 0.733으로 뛴다. 같은 데이터, 같은 모델, 분할 방식만 다르다.

### [표 S-3] 상위 N%를 재검사에 올렸을 때 (시간 순, LightGBM)

| 재검사 비율 | 장수 | fail 검출률 | 정밀도 |
|---|---:|---:|---:|
| 상위 5% | 23 | **0.0%** | 0.0% |
| 상위 10% | 47 | 7.7% | 4.3% |
| 상위 20% | 94 | 23.1% | 6.4% |

무작위로 골랐다면 검출률은 재검사 비율과 같다(5% / 10% / 20%). **상위 20%를 봐도
23.1%밖에 못 잡는다.** 무작위와 거의 차이가 없다.

### [표 S-5] 개선 시도 — 튜닝해도 오르지 않는다

| 시도 | PR-AUC | 기저 대비 |
|---|---:|---:|
| 기본 LightGBM | 0.0636 | 1.15배 |
| 상호정보량 상위 30개 센서 | 0.0625 | 1.13배 |
| 상호정보량 상위 60개 센서 | 0.0635 | 1.15배 |

**최고가 1.27배다. 어떤 시도도 실용 수준에 이르지 못한다.**
"튜닝을 안 해봐서 낮은 것"이 아니라 "해봐도 오르지 않는 것"임을 기록한다.

### 결론 — 실패를 결과로 보고한다

1. **시간 순 분할 조건에서 이 데이터만으로는 웨이퍼 합불 예측이 사실상 되지 않는다**
   (ROC-AUC 0.55~0.59, 상위 5% 재검사 검출률 0%).
2. **무작위 분할은 PR-AUC를 2.5배 부풀린다.** SECOM으로 보고되는 좋은 성능 수치는
   분할 방식을 확인하고 읽어야 한다.
3. 특징 선택·정규화·최근 데이터 학습 등 7가지 시도로도 개선되지 않았다.

이 모듈의 값어치는 예측 성능이 아니라 **평가 방식이 결론을 바꾼다는 것을 같은
데이터로 보인 것**이다. 실제 라인에 올릴 모델이라면 시간 순 검증을 통과해야 한다.

## SECOM 관리도와 이상 구간 분석 — **실데이터만. 이 절이 SECOM의 본론이다.**

실행: `.venv/bin/python src/features/secom_drift.py`

> 앞 절(수율 예측)은 라벨 하나만 썼다. 이 데이터의 본체는 **센서 측정값 692,614개**
> (442 센서 × 1,567 웨이퍼)다. 실제 양산기술 업무에서 센서값으로 하는 일은
> "합불을 맞히는 것"보다 **"평소와 달라진 지점을 찾는 것"**에 가깝다.

### 기준 구간과 관리 한계

앞 40%(627장, 07-19 ~ 09-05)를 '평소'로 잡고, 그 평균 ±3σ를 관리 한계로 삼아
이후 940장을 감시했다. 3σ는 SPC에서 관습적으로 쓰이는 한계다 **(통상범위)**.

### [표 D-1] 관리 한계 이탈

| 센서 | 이탈 횟수 | 이탈률 | 상한 초과 | 하한 미달 |
|---|---:|---:|---:|---:|
| s129 | 301 | **32.09%** | 20 | 281 |
| s078 | 160 | 17.45% | 160 | 0 |
| s006 | 158 | 17.03% | 39 | 119 |
| s122 | 107 | 11.41% | 102 | 5 |

### [표 D-2b] 이상의 성격 — 드리프트와 excursion은 대응이 다르다

| 성격 | 센서 수 | 실무 대응 |
|---|---:|---|
| 정상 | 362 | — |
| **드리프트(지속)** | 28 | 보정·예방 정비 |
| **excursion(일시)** | 52 | 해당 기간 웨이퍼 격리, 원인 조사 |

| 센서 | 성격 | 최대 이탈 | 현재 |
|---|---|---:|---:|
| s275 | excursion | **900.2σ** | 0.8σ |
| s140 | excursion | 870.7σ | 0.6σ |

s275의 구간별 이탈은 `… 0.1, 0.1, 0.1, 836.9, 900.2, 0.8`이다. 두 구간에서만 900배
튀었다가 **정상 복귀**했다. 지속적 이동이 아니다.

> **구현 중 잡은 오류.** 처음에는 "마지막 2구간 평균"으로 현재 상태를 판정했다.
> s275는 (900.2 + 0.8) / 2 = 450이 되어 **excursion이 드리프트로 오분류**됐다.
> 판정 기준을 "마지막 구간 하나(현재 상태)"로 바꿔 고쳤다.

### [표 D-3] pass / fail 분리도 (Cohen's d)

| 효과 크기 | 센서 수 |
|---|---:|
| \|d\| > 0.2 (작음) | 88 |
| \|d\| > 0.5 (중간) | 4 |
| \|d\| > 0.8 (큼) | **0** |

**개별 센서로 합불을 갈라놓을 수 있는 것이 하나도 없다.** 앞 절의 예측 실패
(ROC-AUC 0.55)와 정확히 일관된다. 예측이 안 된 이유가 여기서 설명된다.

### [표 D-5] 이상 구간과 불량의 관계 — **가장 중요한 결과**

개별 센서로는 안 된다면, **여러 센서가 동시에 관리 한계를 벗어난 상태**는 어떤가.
이것이 SPC의 실제 사용법이다.

웨이퍼별 3σ 이탈 센서 수: 중앙 7개, 90분위 14개, 최대 52개.
이탈 센서가 **17개를 넘는 웨이퍼**(상위 5%)를 이상으로 정의했다 **(가정치)**.

| 구간 | 웨이퍼 | fail | fail률 |
|---|---:|---:|---:|
| **이상** | 74 | 11 | **14.86%** |
| 정상 | 1,493 | 93 | 6.23% |

배수 2.39x, 오즈비 2.63, Fisher 정확검정 p = 0.0078.

> **이 수치는 그대로 인용하면 안 된다.** 아래 "시간 순 검증"에서 유의성이 사라진다.
> 기준(평균·σ)은 앞 40%에서 잡았지만 **이상 판정 임계값(17개)을 전체 데이터에서
> 상위 5%로 정하고 같은 데이터로 검정했다.** 임계 선택과 평가가 분리되지 않았다.

### [표 D-4] 주별 결측률 — 장비가 값을 못 남긴 시점

| 주 | 웨이퍼 | 결측률 |
|---|---:|---:|
| 2008-08-31 | 169 | 2.06% |
| 2008-10-05 | 169 | 0.19% |
| **2008-10-19** | 94 | **3.28%** ← 중앙값의 3배 |

결측 급증은 센서·장비 이상 신호일 수 있다. 다만 이 데이터에는 장비 이력이 없어
원인을 확인할 수 없다.

### 정직하게 남길 한계

- 주 단위로 집계하면 이탈 센서 수와 fail률의 관계가 보이지 않는다(10-19 주는 평균
  이탈 10.7개인데 fail률 1.06%). **웨이퍼 단위에서만 보인다.**
- 이상 판정 임계(17개)는 상위 5%로 잡은 가정치다. 값을 바꾸면 배수가 달라진다.
- 센서가 익명화되어 있어(`data_limits.md` L11) 어느 장비의 무슨 물리량이 튀었는지
  알 수 없다. **원인 조사로 연결되지 않는다.**

### [표 R-4] 시간 순 검증 — **여기서 앞의 결과가 무너진다**

가중치를 정한 데이터로 평가하면 과적합이다. 앞 60%(940장)에서만 위험비를 학습하고
뒤 40%(627장)에서 평가했다.

| 항목 | 전체 데이터 기준 | **시간 순 분리** |
|---|---:|---:|
| FDR 통과하며 위험을 높이는 센서 | 27개 | **0개** |
| 상위 5% 웨이퍼의 fail률 | 17.02% | 9.68% |
| 나머지 fail률 | 6.32% | 4.19% |
| 배수 | 2.70x | 2.31x |
| **p** | **0.0103** | **0.1551** |

**학습 구간에서 위험을 높이는 센서가 하나도 남지 않는다.** 가중치를 만들 수 없어
단순 이탈 센서 수로 대체했고, 그 결과도 유의성에 이르지 못한다(p = 0.1551).

### 정직한 결론

1. **효과 크기(배수 2.3~2.7x)는 두 방식에서 비슷하다.** 방향성은 있다.
2. **그러나 시간 순으로 분리하면 통계적 유의성이 사라진다.** 평가 구간이 627장,
   그중 fail 26장뿐이라 검정력이 부족하다. p = 0.1551은 "효과가 없다"가 아니라
   **"이 표본으로는 확인할 수 없다"**에 가깝다.
3. 따라서 **"공정 이상 웨이퍼를 우선 검사하면 불량을 2.4배 잡는다"고 주장하지
   않는다.** 그럴듯한 방향이 보이지만 이 데이터 규모로는 확증되지 않는다.
4. 앞 절(표 D-5)의 p = 0.0078도 임계값 선택과 평가가 분리되지 않은 값이다.
   **표 R-4가 실제 성능에 가깝다.**

> 이 절을 삭제하지 않고 남기는 이유: 분석 과정에서 그럴듯한 결과가 나왔다가
> 엄격한 검증에서 무너지는 일은 실제로 자주 일어난다. **무너진 사실을 기록하는
> 것이 결과를 부풀리는 것보다 중요하다.**
