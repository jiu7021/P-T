공정 센서 관리도 → 웨이퍼 전기 시험 판정 → 칩 내부 Fail Address → (걸러진 다이는) FA 결함 분석
웨이퍼 맵 = WM-811K 실데이터 SEM = Carinthia-S 실데이터 Fail Address = 합성 (공개 데이터 없음) 원인 공정 = 문헌 룩업 (모델 아님)
웨이퍼 맵의 다이 합불과 공간 분포는 WM-811K 실데이터입니다. 패턴 라벨 분류는 CNN 예측이며, 히트맵은 Grad-CAM으로 계산한 판단 근거 영역입니다. 균형 샘플링 표본이므로 여기 표시되는 불량률은 실제 라인 수율이 아닙니다.

분류 결과와 특징

근거 영역(Grad-CAM)이 무엇인가

모델이 "이 웨이퍼는 가장자리 링 패턴이다"라고 답했을 때, 어느 자리를 보고 그렇게 판단했는지를 열지도로 표시한 것입니다. 모델이 낸 점수를 마지막 합성곱 층의 특징맵으로 미분해, 그 판단에 크게 기여한 위치일수록 붉게 칠합니다. 라벨만 내놓지 않고 근거를 함께 보여주기 위해 넣었습니다. 붉은 영역이 실제 불량 분포와 어긋나면, 그 예측은 의심해야 한다는 신호입니다.

웨이퍼 테스트는 전기 시험입니다. 프로브 카드를 다이에 대고 전압을 인가해 출력이 규격에 맞는지 봅니다. 고온 조건도 여기서 겁니다. 이 단계에서 결함 이미지는 보지 않습니다(그건 FA 단계입니다).
어느 좌표의 다이가 불량인지는 WM-811K 실데이터이고, 그 다이가 어느 시험에서 어떤 값으로 걸렸는지와 fail bit 주소는 합성입니다.

리페어 분석 (must-repair 우선)

    불량 모드별 리페어 성공률

    같은 fail 개수라도 모양에 따라 리페어 성공 여부가 완전히 달라집니다. 이것이 Fail Address 분석이 필요한 이유입니다.

    민감도 — 가정이 결론을 얼마나 흔드나

    Good 비율은 모든 조건에서 고정입니다. Good/불량 경계는 실데이터가 정하므로 가정과 무관합니다. 흔들리는 것은 합성이 정하는 Repairable ↔ Fail 배분뿐입니다.

    제시된 항목은 후보이며 확정 판단이 아닙니다. 최종 판단은 엔지니어가 수행합니다.
    이 탭은 FA(불량 분석) 단계입니다. 웨이퍼 테스트에서 Fail로 걸러진 다이를 나중에 뜯어 결함을 눈으로 확인하는 작업이며, 웨이퍼 테스트와 같은 단계가 아닙니다. 또한 여기 이미지는 Module 1·2의 웨이퍼와 다른 라인·제품·시점의 것입니다. 같은 웨이퍼를 추적하는 것이 아닙니다.

    SEM 이미지와 마스크는 Carinthia-S 실데이터입니다. 데이터셋이 결함 클래스 이름을 공개하지 않아 라벨은 숫자 1~6뿐입니다. 숫자에 임의로 결함 용어를 붙이지 않고, 마스크에서 측정한 형태를 근거로 원인 공정 후보를 조회합니다. Carinthia-S가 어느 공정 층인지도 공개되지 않았으므로, 후보는 "이 형태의 결함이 일반적으로 어느 공정에서 비롯되는가"이지 "이 이미지의 원인이 무엇인가"가 아닙니다.

    이미지 선택

    결함 위치

    원본 SEM은 밝기 표준편차 중앙값이 10.8(0~255)로 매우 낮아 그대로는 결함이 잘 보이지 않습니다. 대비 강조는 2~98 백분위로 선형 스트레칭한 표시용 처리이며, 모델 입력과 형태 측정값은 원본 그대로를 씁니다.

    원인 공정 후보 (문헌 룩업 · 학습 대상 아님)

    이 탭은 합성이 하나도 없습니다. 실제 fab 라인에서 89일간 기록된 공정 센서값과 웨이퍼 합불 결과를 그대로 씁니다 (UCI SECOM).

    데이터

    월별 fail률 — 드리프트가 실재한다

    fail률이 22.2%에서 2.9%로 8배 가까이 흔들립니다. 이 사실이 분할 방식을 결정합니다.

    분할 방식이 결론을 바꾼다 — 이 절이 핵심

    무작위로 섞어 나누면 미래 웨이퍼로 학습해 과거를 맞히는 셈이 됩니다. 실제 라인은 과거로 학습해 다음 로트를 판단합니다. 같은 데이터·같은 모델에 분할 방식만 바꿔 비교했습니다.

    상위 N%를 재검사에 올린다면

    개선 시도 — 튜닝해도 오르지 않는다

    기여 센서 (참고)

    관리도 — 센서값이 평소 범위를 벗어난 시점 앞 40%를 '평소'로 잡고 ±3σ를 한계로

    가로 = 시간 순 웨이퍼. 회색 = 측정값, 점선 = 관리 한계(±3σ), 굵은 선 = 평소 평균, 빨간 점 = 불량 웨이퍼, 세로 구분선 = 기준 구간의 끝

    이상의 성격 — 대응이 다르다

    이상 구간과 불량의 관계 — 핵심

    센서별 위험도 — 다중비교 보정을 먼저 한다

    센서 열화 의심 — 이탈이 점점 잦아지는가

    시간 순 검증 — 여기서 위 결과가 무너진다

    결론 — 실패를 결과로 보고합니다

    AI는 후보와 근거만 제시합니다. 원인 공정을 판정하지 않습니다. 판정은 엔지니어가 하고, 그 판정이 쌓이면 학습 데이터가 됩니다.

    피드백 루프

    SEM 이미지
  └→ 마스크에서 형태 측정            (관측 사실)
      └→ cause_map.yaml 룩업
          └→ 후보 + 근거 + 논문 출처 제시   ← AI가 하는 일은 여기까지
              └→ 엔지니어가 판정              ← 사람이 결정
                  └→ verdicts.jsonl 누적 (append-only)
                      └→ 준비도 판단
                          └→ 충분하면 학습 데이터로 내보내기

    설계 원칙

    1. AI는 판정하지 않는다. 후보·근거·출처를 나열할 뿐 선택하지 않는다.
    2. append-only. 기존 기록을 수정하지 않는다. 판단이 바뀐 이력도 데이터다.
    3. 표본이 부족하면 학습을 거부한다. 적은 표본으로 그럴듯한 모델을 만드는 것이 이 프로젝트에서 가장 위험한 실패다.
    4. 후보 목록 밖 판정을 막지 않는다. 그것이 쌓이면 룩업 표를 개정할 근거가 된다.

    학습 준비 기준 가정치

    조건기준
    엔지니어 판정 총 건수≥ 100
    30건 이상 모인 공정 종류≥ 2
    공정당 최소 건수≥ 30

    공개된 기준이 없습니다. 클래스당 수십 건 미만이면 검증셋 분리조차 성립하지 않습니다(Module B의 class 5가 4장이라 F1이 무의미했던 것과 같은 문제). 이 값을 넘겨도 성능이 보장되지는 않습니다. 하한일 뿐입니다.

    판정 입력 (CLI)

    # 후보 확인 (판정하지 않음)
python src/model/feedback.py show --image <filename>

# 엔지니어 판정 기록
python src/model/feedback.py add --image <filename> \
    --process CMP --engineer <이름> \
    --confidence high --rationale "연마 방향과 일치"

# 누적 현황·학습 준비도
python src/model/feedback.py stats

    대시보드는 브라우저 저장소를 쓰지 않으므로 판정 입력은 CLI로 받습니다. 이 화면은 조회 전용입니다.

    이 프로젝트가 주장하는 것과 주장하지 않는 것

    • 웨이퍼 맵의 다이 합불과 공간 분포는 WM-811K 실데이터입니다.
    • SEM 결함 이미지와 세그멘테이션 마스크는 Carinthia-S 실데이터입니다.
    • Fail Address는 공개 데이터가 없어 합성했습니다. 절대값이 실제 제품과 같다고 주장하지 않습니다.
    • 원인 공정 추정은 모델이 아니라 문헌 기반 룩업이며 확정 판단은 사람이 수행합니다.
    • 따라서 주장하는 것은 모델 성능이 아니라 분석 흐름의 설계와 의사결정 근거의 가시화입니다.

    데이터 계층 — 혼동 금지

    계층단위데이터
    웨이퍼 맵다이 1개 = 점 1개실데이터
    Fail Address다이 내부 셀 주소합성
    SEM결함 1개 확대실데이터

    두 데이터셋은 서로 다른 라인·제품·시점의 것입니다. Module A와 B를 같은 웨이퍼의 데이터인 것처럼 연결하지 않습니다. 대시보드가 잇는 것은 업무 흐름의 재현이지 동일 웨이퍼 추적이 아닙니다.
